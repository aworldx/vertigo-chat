# Community-каталог геоигры

Подготовлен 2026-10-06. Это исходные локации игры, **не готовые вопросы**.
Сервер игры проверяет доступность выбранных панорам и определяет страну/город
перед раундами. Фотографий здесь нет; панорамы показывает Google SDK.
Импортёр работает без сетевых запросов.

Итого: **10 790 уникальных локаций**, 10 790 связей с источниками. В этих двух
снимках пересечений по правилам идентичности не найдено. Название `aaw-5000`

An Arbitrary World не является A Community World и не заявляется ручной подборкой.

Карты опубликованы в репозиториях с MIT; копии лицензий сохранены рядом с экспортами.
Автор Gorgeous Touge Roads явно разрешает использование в альтернативных играх
в [README](https://github.com/itsjustduc/geoguessr-stuff#geoguessr-stuff).
Лицензии наборов не заменяют условия Google на показ самих изображений.
Все имеющиеся `panoId` относятся к **Google Street View**, не к Mapillary.

## Файлы и происхождение

- `sources/*/manifest.json`: постоянный ID источника, исходный ID карты,
  автор, лицензия, способ отбора, формат, провайдер, commit SHA, точный URL и SHA-256 экспорта.
- `sources/*/locations.*`: неизменённые исходные экспорты, включая авторские метки.
- `sources/*/LICENSE`: исходные уведомления о лицензиях.
- `catalog.json`: подготовленный каталог со стабильными ID локаций, историей
  версий источников и отдельными записями каждой карты.

`map_id` Touge — GeoGuessr `6305565fde2667656468e9b2`, опубликованный самим автором;
`map_id` AAW — ключ `aaw-5000` из каталога GeoGuess-Maps.
Ни один из двух экспортов не содержит собственных ID отдельных записей.
Поэтому `record.id` имеет вид `coordinate:lat,lng` и `id_kind=derived-coordinate`.
Это наши производные ключи, а не выдуманные upstream ID. Если другой экспорт
содержит `id` / GeoJSON `Feature.id`, он переносится как `id_kind=native`.
Большие числовые ID сохраняются без потери точности.

`panoId` переносится без перекодирования; для 92 записей Touge берётся из
`extra.panoId`, для остальных 5 743 — из верхнего поля. Сохраняются ракурс
(`heading/pitch/zoom`), дата панорамы, теги и коды страны/региона, если они есть.
Полный оригинал позволяет восстановить остальные поля.

## Правила пополнения без дублей

1. Источник идентифицируется постоянным `source.id`. Не менять его при обновлении
   версии и не использовать имя файла новой версии как новый источник.
2. Локация имеет неизменный `loc_…` ID. Совпадение провайдера и ID панорамы **или**
   координат до 7 знаков связывает импорт с существующей локацией.
   Близкие, но разные дороги по расстоянию не объединяются.
3. Сохраняются исторические координаты и ID панорам. Смена `panoId` при тех же
   координатах не создаёт новую локацию. Стабильный исходный ID записи также
   позволяет обновить одновременно координаты и панораму.
4. Ракурсы и авторские метки каждой карты хранятся отдельно. При пересечении
   наборов игра выбирает по `location_id`, а не по числу записей.
5. Если разные ключи указывают на разные существующие локации, весь импорт
   отклоняется. Автоматического сомнительного слияния нет.
6. Повтор той же версии не меняет каталог. Новая версия добавляет/обновляет записи,
   сохраняя отсутствующие в ней старые. Это **добавление**, не полная синхронизация
   с удалениями. `entry.revision` показывает происхождение сохранённой записи.
   Известная устаревшая версия и изменение содержимого существующей версии отклоняются.

Ограничение: если у записи нет собственного ID и одновременно изменились координаты
и ID панорамы, достоверно узнать старую точку невозможно. Такая запись может стать
новой; потребуется ручное сопоставление. При отсутствии panoId разные координаты,
которые в будущем разрешатся в одну панораму, тоже требуют проверки перед игрой.

## Повторный импорт

Из корня репозитория, в закреплённой Linux-среде:

```sh
docker run --rm -v "$PWD:/work" -w /work/apps/api golang:1.27.1-trixie \
  go run ./cmd/geo-import \
  -manifest /work/data/geo/sources/touge/manifest.json \
  -catalog /work/data/geo/catalog.json
```

По умолчанию выводит только предполагаемые изменения. Для записи добавить `-apply`.
Для второго набора заменить `touge` на `aaw`. Родительский каталог должен существовать.
Обновление файла атомарное; параллельный писатель получает отказ по `.lock`.
После аварийного завершения оставшийся `.lock` удаляют вручную **только после
проверки, что импорт больше не выполняется**. Это локальный каталог подготовки,
не хранилище для нескольких серверов.

Для новой версии:

1. Сохранить новый экспорт отдельным файлом рядом со старым, не теряя предыдущий.
2. Обновить manifest: `file`, `revision`, `download_url`, `sha256`; сохранить `source.id`.
   Для нового набора добавить собственную папку с автором, лицензией и manifest.
3. Запустить предварительный импорт, проверить счётчики и затем применить `-apply`.
4. Повторить импорт: ожидаются нули добавлений и обновлений.

Manifest строгий; неподходящий формат, неверная контрольная сумма, неполные
координаты и конфликтующие ID отклоняются до записи.

## Отбор для игры

Каталог целиком не проходил ручную проверку качества каждого вопроса.
У Touge сохранены `unused`, `future`, `provisional`, `*_removal`, `*_removed`,
`reconsider`, `inaccurate` и другие рабочие теги. Они не означают готовность к показу;
такие записи требуют отдельного отбора. Отсутствие тега тоже не является проверкой.

Игровой провайдер отсекает рабочие теги, проверяет доступность Google-панорам и
определяет русские/английские варианты страны и города. Общий набор имеет приоритет
перед горными дорогами; среди кандидатов предпочитаются адреса с признаками
городской застройки. Это повышает вероятность города, но не гарантирует его.
Подробнее: [реализация игры](../../docs/design/geo-chat/IMPLEMENTATION.md).

## Проверки

В Docker: Go `test -race`, `vet`, `golangci-lint` для `internal/geocatalog/...`
и `cmd/geo-import`. Покрыты повторы после чтения с диска, порядок записей,
пересечения, ракурсы, смена ID/координат, пополнение и обновление, сохранение
старых записей, большие ID, неверные файлы, checksum, блокировка и атомарность.
Оба полных исходных набора входят в интеграционный тест.

Также выполняется реальный CLI-импорт обоих наборов и повтор: 0 новых локаций,
0 новых связей, 0 обновлений; содержимое файла не меняется.
Проверки HTTP/PostgreSQL/browser самой игры описаны в отчёте реализации.
