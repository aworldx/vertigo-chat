# Архитектурные договорённости

Текущий стек: Go API, React/TypeScript, PostgreSQL и отдельный YouTube worker.
Phoenix удалён из main; старые реализации доступны в истории Git и ветке
`legacy-phoenix-chat`. Они не участвуют в сборке, тестах или работе сервиса.

## Go

Направление зависимостей: `adapters → application → domain`.

- `domain` содержит бизнес-правила и не зависит от HTTP, PostgreSQL и процессов.
- `application` координирует сценарии и определяет необходимые порты.
- `adapters` реализует HTTP, WebSocket, хранение и внешние интеграции.
- `cmd/api` связывает зависимости. HTTP-обработчики проверяют вход и вызывают
  сценарии, а не реализуют правила продукта.
- Контекст владеет своими данными; прямой доступ к внутренним репозиториям
  соседнего контекста не допускается. Один владелец записи и миграций.

## React

Направление зависимостей: `app → pages → features → shared`.

Композиция страницы, UI-компоненты, hooks/состояние и API разделены. Render чистый.
Между features нет прямых зависимостей; потребители используют публичный API.
Новый код — строгий TypeScript без массовых исключений и `any`.
Рабочие entrypoints: `apps/web/src/app/main.tsx` и `apps/web/css/web.css`.

## Контракты и проверки

HTTP/WebSocket DTO согласованы с `contracts/`; сгенерированные типы обновляются
вместе с контрактами. Тестовая исходная PostgreSQL-схема
`script/fixtures/legacy-schema.sql` сохранена для Go-проверок: она не требует
Phoenix и не является новой production-миграцией.

Целевые Docker unit/HTTP/PostgreSQL/browser-проверки обязательны для изменённой
поверхности и соседних сценариев. UI проверяет основной агент через verifier.
Полный `script/check` запускается только по отдельному запросу.
