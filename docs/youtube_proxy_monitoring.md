# Проверка YouTube-прокси

YouTube worker раз в час перечитывает смонтированный файл `YOUTUBE_PROXY_SOURCE_FILE` (в production — существующий `.music_proxies`). Для каждой корректной уникальной записи он через этот прокси получает небольшой фрагмент тестового YouTube-видео командой `yt-dlp --test`. Параллельно проверяются не более четырёх прокси; каждая попытка ограничена 18 секундами. Адреса и учётные данные не попадают в логи и метрики.

Рабочие прокси выбираются первыми при загрузке ролика. Пока первая проверка не завершилась, worker использует исходный порядок `YOUTUBE_PROXY_FILE`. В production это отдельная копия с проверенными записями в начале, чтобы не задерживать первый ролик после перезапуска. Изменения основного файла подхватываются на следующем цикле без перезапуска.

Prometheus опрашивает `youtube-worker:4001/internal/metrics`: `chat_youtube_proxies_working`, `chat_youtube_proxies_total`, `chat_youtube_proxy_source_read_success`, `chat_youtube_proxy_checked_timestamp_seconds`. Grafana показывает рабочие/все прокси и возраст проверки. Оповещение срабатывает, когда 10 минут нет рабочих прокси или файл нельзя прочитать. Лог `youtube_proxy_scan` фиксирует только общее и рабочее количество и длительность.
