# Исследование GeoGuess и GeoGuessLite

Дата: 2026-10-06. Это исследование, не внедрение. Код чата и production не менялись.

## Вывод

Для согласованного формата — открытый раунд в общей комнате без лобби, необязательное участие, ответы словами и существующий дизайн — предпочтительна собственная небольшая игровая логика в Go с готовым просмотрщиком MapillaryJS в React. GeoGuessLite полезен как референс сбора идентификаторов снимков, подготовки раундов и серверного подсчёта. Перенос всей игры создаст больше интеграционных зависимостей, чем повторное использование этих частей. Это инженерная оценка по исходникам, не результат нагрузочного сравнения.

## GeoGuess

Источники:

- [StreetViewService.js](https://github.com/GeoGuess/GeoGuess/blob/692bf60d4a402ab70c6b9a4c8862e5aef156a2ee/src/plugins/StreetViewService.js)
- [StreetView.vue](https://github.com/GeoGuess/GeoGuess/blob/692bf60d4a402ab70c6b9a4c8862e5aef156a2ee/src/pages/StreetView.vue)
- [MapAreas.vue](https://github.com/GeoGuess/GeoGuess/blob/692bf60d4a402ab70c6b9a4c8862e5aef156a2ee/src/components/map/MapAreas.vue)
- [package.json](https://github.com/GeoGuess/GeoGuess/blob/692bf60d4a402ab70c6b9a4c8862e5aef156a2ee/package.json)
- [лицензия MIT](https://github.com/GeoGuess/GeoGuess/blob/692bf60d4a402ab70c6b9a4c8862e5aef156a2ee/LICENSE)

Как получает места: генерирует случайную координату мира или точку внутри GeoJSON; также принимает заданные точки. Через Google Maps JavaScript StreetViewService ищет ближайшую панораму. Для случайного мира радиус поиска 100 км; для заданной точки 50 м. Неуспешный поиск повторяется. Каталог карт по умолчанию внешний: maps.geoguess.games/maps.json. Собственного комплекта фотографий в коде нет.

Есть режим угадывания страны/области кликом по полигону. Код страны определяется через Nominatim либо заданные полигоны. Это не свободный текст, синонимы и опечатки не обрабатываются как игровые ответы.

Технологии: Vue 2.7, Vuex, Vuetify 2, Firebase 8, Google Maps JavaScript API. Dockerfile собирает приложение и обслуживает его через nginx; Firebase и Google остаются внешними зависимостями. Это не Go-сервис и не готовый React-компонент.

В multiplayer координаты раунда передаются через Firebase; клиент вычисляет результат и пишет finalScore/finalPoints. Для нашего серверного авторитета очков этот путь нельзя переносить без переработки. В просмотренном getStreetView нет общего ограниченного бюджета повторов при отсутствии подходящих панорам — для собственного адаптера нужны deadline и предел попыток.

Вердикт: подходит как отдельная классическая игра с Google Street View или референс выбора мест. Менее подходящая основа для нашего формата и стека.

## GeoGuessLite

Источники:

- [GameMap.vue](https://github.com/spider-hand/GeoGuessLite/blob/37975d9188b82cfc45f62bf11a6e7fc6ff203ecb/client/src/components/pages/Game/GameMap.vue)

- [with_friends_games/service.py](https://github.com/spider-hand/GeoGuessLite/blob/37975d9188b82cfc45f62bf11a6e7fc6ff203ecb/server/src/features/with_friends_games/service.py)
- [лицензия MIT](https://github.com/spider-hand/GeoGuessLite/blob/37975d9188b82cfc45f62bf11a6e7fc6ff203ecb/LICENSE)

Цепочка данных:

1. Скрипт проходит покрытие Mapillary на zoom 5, берёт из слоя overview `image_id` и `is_pano`, сохраняет JSONL.
2. Другой скрипт импортирует JSONL в PostgreSQL, таблицу images. Готового JSONL/наполненной БД в скачанном репозитории не обнаружено. Сборщик самостоятельно не запускался, токен не запрашивался.
3. Игра случайно выбирает 10 панорам `WHERE is_pano = TRUE ORDER BY RANDOM()` и через Graph API получает computed_geometry. Если удалось подготовить пять мест, создаётся игра; иначе возвращается game_images_unavailable.
4. Фронтенд передаёт imageId библиотеке MapillaryJS. Фотографии загружает просмотрщик, они не входят в репозиторий игры.
5. Ответ — latitude/longitude. Сервер считает расстояние и очки. У цели нет подготовленного города или набора текстовых вариантов.

В просмотренном пути нет отбора по стране, качеству кадра, узнаваемости или уровню сложности. Наличие корректной геометрии ещё не проверяет полезность кадра для викторины. Массовый импорт не является готовым редакционным каталогом.

Multiplayer: до 100 участников по константе, 60 секунд на раунд, 15 секунд между результатами. Есть лобби и код комнаты. Новое присоединение после старта запрещается; существующий участник может восстановить соединение. Когда все участники ответили, раунд может раскрыться раньше таймера. Для общего чата это нужно менять: состав отвечающих заранее неизвестен. Число 100 — конфигурация кода, не доказанная нагрузочным тестом вместимость.

Технологии: Vue 3/TypeScript, Python 3.14 на AWS Lambda, API Gateway, SQS, Secrets Manager, Firebase Authentication/Realtime Database, PostgreSQL с Neon в конфигурации, Mapbox для карты и MapillaryJS для снимков. Штатный запуск предполагает внешнюю инфраструктуру. Перенос целиком не избавляет от работы по интеграции в Go + React.

## Библиотека и условия использования

[MapillaryJS](https://mapillary.github.io/mapillary-js/docs/) — отдельный готовый JavaScript-просмотрщик, который можно обернуть React-компонентом. Он поддерживает просмотр, масштабирование и переходы по снимкам; для игры не требуется переносить Vue-приложение GeoGuessLite.

[Mapillary FAQ](https://help.mapillary.com/hc/en-us/articles/8348198426396-Mapillary-FAQ) указывает бесплатное использование, включая коммерческие сценарии. Нужен собственный клиентский токен; квоты, доступность сети и качество выбранных регионов требуют проверки на реальном аккаунте. Бесплатные снимки не означают бесплатные AWS/Mapbox или наш хостинг.

[Снимки Mapillary имеют CC BY-SA](https://help.mapillary.com/hc/en-us/articles/115001770409-CC-BY-SA-license-for-open-data). Условия изображений отдельны от MIT игрового кода; атрибуцию и ссылки нельзя просто удалить ради скрытия ответа. При заимствовании MIT-кода сохраняются copyright/license notices.

GeoGuess использует JavaScript API Google, а не бесплатный Maps Embed. [Maps Embed API действительно бесплатен и требует ключ](https://developers.google.com/maps/documentation/embed/usage-and-billing), но подмена им используемого SDK не является заменой одной настройки. Цены и правила применяются к реально выбранным Google API.

Для географических названий GeoGuess использует публичный Nominatim. [Его политика](https://operations.osmfoundation.org/policies/nominatim/) ограничивает сервис суммарно одним запросом в секунду, требует идентификации и атрибуции, запрещает autocomplete и систематический сбор. Для собственного регулярно пополняемого каталога нужен подходящий провайдер/локальные данные; не следует автоматически переносить публичный endpoint в поиск ответов или массовую обработку.

## Предлагаемая интеграция

- Go-контекст игры владеет открытым раундом, дедлайном, скрытыми ответами и результатами. Используем сессию чата; участия в отдельном лобби нет.
- React-панель соответствует согласованным макетам, мобильный ответ текстовый. Библиотека просмотра — отдельная зависимость UI.
- Адаптер источника получает реальные снимки Mapillary и координаты. Заранее проверенный запас позволяет начинать раунд без ожидания цепочки внешних API.
- Серверный каталог дополняется страной, населённым пунктом и допустимыми названиями. Для улицы вне населённого пункта вопрос о городе не задаётся. Неоднозначные приграничные/административные случаи исключаются или получают явно определённое правило.
- Нормализация текста, варианты русских/латинских названий, правила опечаток и географическая неоднозначность реализуются отдельно. Автоматический ближайший город не следует считать правильным ответом без проверки.
- Одинаковая оценка страны/города на всех устройствах; карта на desktop не должна создавать преимущество точного попадания перед текстовым ответом mobile.
- Воздержание не создаёт проигрыш. Раунд завершается общим дедлайном, а не ответами текущего списка присутствующих.
- Клиентский просмотрщик/публичные imageId могут позволить технически подготовленному игроку узнать координаты через источник. Скрытые ответы других игроков и серверные очки обеспечиваются отдельно; абсолютную защиту от поиска по снимку не обещаем.

Ближайший технический эксперимент: получить собственный токен Mapillary, проверить небольшую репрезентативную выборку по нужным регионам, качество/доступность снимков и пригодность для текстовых вопросов. После этого утверждать источник. До такого эксперимента рекомендация Mapillary условна.
