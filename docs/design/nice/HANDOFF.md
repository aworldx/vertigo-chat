## Зафиксированное оформление

Все размеры/селекторы в proposal.css; он является дизайн-ресурсом и не подключён к приложению. Существующая сетка сохранена: desktop внешние отступы 16px, gap 14px; mobile 10px. Текущие Manrope (Vertigo Text) и Oswald (Vertigo Display) сохранены. Текст сообщений 15px/1.65 desktop и 14px/1.6 mobile. Основной текст #203e50, акцент #175f96, молочные панели #fffdf5 с непрозрачностью 91–93%, граница #b4c9cb.

Фон версии 2: assets/promenade-white-karmik-v2.png. По уточнению пользователя оба стула белые, ближний развёрнут к зрителю; светлый кремовый Кармик с янтарными глазами сидит на сиденье и является частью единой иллюстрации. Отдельный чёрный sprite в макете скрыт. Для будущей реализации нужен прозрачный интерактивный target по положению кота, как у существующей темы, и отдельный вариант картинки без кота для настройки скрытия. В этом дизайн-этапе они не реализованы.

Desktop/tablet: рисунок высотой viewport − 170px, right −70px bottom; сверху переход от #e8f0f0 до прозрачного между 170 и 320px, слева переход 30–58% desktop; tablet использует мягкий переход до 40%. Точные правила в proposal.css. Mobile и landscape сохраняют cover, mobile position 78% bottom. На телефоне фигуру частично перекрывает лента: полная видимость кота во всех состояниях не является свойством этого макета. Кармик не занимает отдельное место в потоке страницы и не сдвигает ввод.

PNG версии 1 сохранены в mock/, фон — assets/promenade-v1.png, CSS — proposal-v1.css, скрипт — capture-v1.mjs. Актуальные эталоны — mock-v3/.
Ресурсы шрифтов: apps/web/public/fonts/manrope-variable.ttf и oswald-variable.ttf. Фон создан встроенным image_gen; точные запросы сохранены в PROMPT.txt и PROMPT-v2.txt. Исходник оставлен в стандартной папке генераций, проектная копия находится в assets.

## Критерии будущей приёмки реализации

Для КАЖДОГО из пяти viewport выше нужны исходный PNG, PNG текущей Docker-сборки с теми же fixtures/auth и side-by-side плюс overlay/diff. Пока реализации и этой тройки нет, финальная приёмка не проводилась.

- PASS только если шапка, навигация, сетка и положение composer совпадают с эталоном; иначе FAIL.
- PASS только при совпадении исходного фона, crop, шрифтов, размеров, отступов, цветов, границ и прозрачности; иначе FAIL.
- PASS только если первый блок виден, лента прокручивается, фон не занимает отдельный экран, декоративные элементы не закрывают controls во всех трёх scroll-state; иначе FAIL.
- PASS только если нет горизонтального overflow, текст читаем, hover/focus/disabled/loading различимы; иначе FAIL.
- PASS только после сценариев verifier для отправки, команд, меню, настроек и приватных сообщений в Docker; иначе FAIL.

Не покрыты этим предложением: отдельные макеты настроек/диалогов/плеера, режим без рамок, тёмный вариант, медиа-сообщения и все пользовательские цветовые настройки. Их нужно подготовить перед внедрением соответствующих поверхностей. Unit/HTTP/PostgreSQL tests не запускались: изменения ограничены дизайн-артефактами.
