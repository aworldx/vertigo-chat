# OpenAI в Grafana

Дашборд `Vertigo chat — мониторинг` содержит три независимые группы показателей.

## Дневной бюджет ботов

Общий лимит `OPENAI_BOT_DAILY_TOKEN_LIMIT` (по умолчанию 120000), расход,
остаток, процент использования и остаток до остановки. Хичкок, обновление
памяти диалогов и Кармик используют один ledger `bot_daily_usages`.
`OPENAI_BOT_TOKEN_WARNING_PERCENT` (по умолчанию 90) определяет фактическую
остановку. Например, при расходе 108000 остаётся 12000 до полного лимита,
но новые запросы ботов уже прекращаются. Запущенный запрос может пересечь порог.
День считается с `OPENAI_BOT_UTC_OFFSET_MINUTES` (по умолчанию UTC+3).

Это учёт приложения, а не точная сверка биллинга: ledger отражает успешно
записанные результаты; usage неуспешных попыток/ответов может в него не попасть.
После перезапуска данные берутся из PostgreSQL. Ошибка чтения не выглядит как
нулевой расход. При отключённом лимите (`<= 0`) расход доступен, остаток и
процент не показываются.

## Ошибки и лимиты ответов

`chat_openai_requests_total{bot,outcome}` считает каждую исходящую попытку,
включая retry Хичкока и запросы сводки памяти. Отдельные карточки показывают
ошибки каждого бота за выбранный период. Причины: `http_429`, `http_4xx`,
`http_5xx`, `http_other`, `timeout`, `canceled`, `transport_error`,
`invalid_response`. HTTP 429 может означать как rate limit, так и ограничение
биллинга; здесь он не выдаётся за доказательство исчерпания денег.
Ошибки очереди/БД до исходящего запроса не входят в этот счётчик.
Счётчики живут в процессе; Prometheus хранит историю, `increase` учитывает reset.
Счёт за период — оценка по scrape и требует хотя бы двух наблюдений.

`chat_openai_rate_*{bot,resource}` содержит числовые заголовки `x-ratelimit-*`
для tokens, requests и project-tokens, если OpenAI их вернул. В дашборде
показаны токены: лимит, последний остаток, время до reset и возраст снимка.
Это ограничение частоты запросов, не денежный баланс и не дневной бюджет чата.
Значения ботов нельзя складывать: они могут использовать одну общую квоту.
После reset или 15 минут остаток скрывается до нового ответа; восстановленный
остаток не угадывается. Ответ без нужных заголовков сбрасывает прежний снимок.

## Расходы аккаунта в долларах

Настроить отдельно от ключа ботов:

```dotenv
OPENAI_COSTS_ADMIN_KEY=...
# Необязательно, для явного выбора организации:
OPENAI_COSTS_ORGANIZATION_ID=...
```

Используется только `GET /v1/organization/costs`, раз в пять минут в фоне.
Дневная и месячная суммы охватывают все проекты выбранной организации;
границы дня и календарного месяца — UTC, независимо от дня бюджета ботов.
Admin key не заменяет `OPENAI_API_KEY` и не используется для генерации ответов.
Секреты хранятся в закрытом `.env`, не в дашборде и не в Git.

Данные Costs API могут приходить с задержкой. Карточки показывают расходы,
**не остаток предоплаченных кредитов**. Показано время успешного опроса.
Без ключа состояние — «Нет admin key»; при ошибке опроса/старых данных суммы
скрываются, а последнее время успеха остаётся. Запросы поддерживают pagination;
неполный или некорректный ответ не превращается в ноль.

Метрики доступны только на защищённом `/internal/metrics`. Тексты сообщений,
ключи, идентификаторы пользователей и тела ошибок туда не попадают.

Источники: [Costs API](https://platform.openai.com/docs/api-reference/usage/costs),
[Admin API keys](https://developers.openai.com/api/docs/guides/admin-apis),
[rate-limit headers](https://developers.openai.com/api/docs/guides/rate-limits#rate-limits-in-headers),
[Prometheus increase](https://prometheus.io/docs/prometheus/latest/querying/functions/#increase).

Изменение подготовлено в Go-ветке. Для появления метрик на VPS требуется
отдельный выпуск Go API и обновлённой конфигурации Grafana. Публикация и
production rollout этой задачей не выполняются.
