без коммита. Эталон: `0734268bd59a6a84178d3040fefd805e707ff6cb`, checkout

## Граница этапа

В отдельный React-компонент перенесены базовые строки участников: гостевой
значок, ник с обрезкой длинного текста, публичное обращение по клику/Enter,
взаимоисключающие «В сети» / «Нет связи», текущая запись с live status,
счётчик, удаление завершённых сессий и responsive sidebar. Отсутствующий
собеседник недоступен для обращения. При локальном обрыве только собственная
строка сразу показывает «Нет связи»; остальные сохраняют последний серверный
снимок. Восстановление сохраняет ID строки. Завершённая/дублирующая вкладка
не показывает устаревший список как текущий.

Go Peer DTO дополнен `registered` и `self`. Они определяются по доверенной
identity и ID сессии на сервере, а не по нику или site-cookie в браузере.
Identity key, resume secret и user ID не включаются в Peer. Список по-прежнему
читается из существующих chat_sessions; новых таблиц, миграций и write-path нет.
Владельцы данных не меняются. Совместно обновляются контракт, Go и React.

Это **первый срез списка, не готовность всего sidebar или комнаты**.
Зарегистрированные участники пока имеют статический значок аккаунта;
их сохранённое оформление, ранги, открытие анкеты, личное обращение по двойному
клику, музыка, bot/Кармик и настройки ещё не перенесены. Снимки сравнивают
только гостевые строки в стандартной теме. Счётчик Go учитывает реальные
chat sessions; legacy дополнительно показывает Хичкока, который ещё не перенесён.
Меню и composer продолжают отличаться. Эти области не объявляются визуально
принятыми. Публичное обращение заменяет draft и фокусирует ввод; известный
legacy-дефект замены уже отредактированного draft описан в отчёте ленты.

## Воспроизведение

```sh
GO=/tmp/chat-go-sdk/go/bin/go GOCACHE=/tmp/chat-go-cache \
LEGACY_ROOT=/private/tmp/chat-web-legacy-0734268 \
WEB_VERIFICATION_SUITE=chat-online KEEP_MIGRATION_STAND=1 \
GO_WEB_PORT=4054 LEGACY_WEB_PORT=4055 script/verify-go-web
```

Go: `http://127.0.0.1:4054/`, legacy: `http://127.0.0.1:4055/`.
Оба стенда используют собственные disposable PostgreSQL БД со схемой chat_test
и одинаковыми go-web fixtures. Assets Go копируются в каталог стенда;
последующие локальные сборки не меняют работающий стенд.

Chromium Playwright, locale ru-RU, timezone Europe/Moscow, scale 1, reduced
motion. Viewport: 390×844, 768×1024, 1440×900, 767×900.
На каждый backend входят две независимые browser-сессии: `online-reader` и
`online-guest-with-long-n` (24 символа). На tablet/desktop сравниваются строки
в состояниях active с длинным ником, self, hover, keyboard focus, reconnecting,
restored. На phone и ниже breakpoint проверяются скрытие sidebar и отсутствие
горизонтального overflow. Снимки полного экрана сохраняются как контекст,
но совпадение полной комнаты не утверждается.

Сравнение строк не подменяет CSS, высоты, шрифты или фон; масок нет.
Отдельно сравниваются координаты/размеры строки и ника, шрифт, размер/вес,
line-height, цвет, text-overflow, focus-visible и computed outline.
Перед сохранением требуется два подряд одинаковых снимка каждой версии;
повторные снимки не подбираются до совпадения old/new.

Финальное сравнение: 12 пар, из них 10 pixel-exact. На keyboard-focus
отличаются 1 пиксель на tablet и 3 на desktop, исключительно снаружи поля
ника в углу нативного `outline: auto`. Координаты, размеры, computed outline
и весь текст совпадают. По расположению и величине это различие сглаживания
нативной рамки Chromium; CSS продукта не менялся. Зафиксирован узкий допуск:
не более 3 пикселей, не более 7 уровней на канал, только во внешней полосе
шириной 2 px вокруг nickname control, только для keyboard-focus при одинаковых
computed styles. Внутри control и в остальных состояниях допуск нулевой.
Raw diff сохранён; отдельный тест запрещает расширение допуска на содержимое,
изменение геометрии или более крупные различия. Для настоящего разрыва WebSocket обе вкладки переходят на
about:blank, затем возвращаются на /chat в том же tab context: sessionStorage
сохраняется и сессия восстанавливается. Это необходимо, поскольку Chromium
offline не гарантирует закрытия уже открытого legacy-сокета. Локальный offline
Go отдельно проверяет немедленную замену собственного статуса.

## Проверки и ручное принятие

Снимки old/new/diff и report.json: `apps/web/migration-results/chat-online/`.
Финальный browser-запуск против оставленных стендов:

```sh
cd apps/web
LEGACY_SHA=0734268bd59a6a84178d3040fefd805e707ff6cb \
node --import=tsx browser/chat-online-verification.ts \
http://127.0.0.1:4054 http://127.0.0.1:4055
```

Финальный `mix precommit` прошёл: 411 ExUnit, 14 frontend, 3 browser,
Go lint/vet/race/build, contracts, TypeScript/ESLint/Prettier, Credo/Dialyzer. `check-infrastructure` прошёл с прежними предупреждениями
info.license, Snapshot без HTTP path и Docker RUN. TypeScript/ESLint и все
14 frontend-тестов прошли после последнего изменения.

`verify-go-chat` прошёл: PostgreSQL проверяет guest/registered/self,
active → reconnecting → active с тем же session ID, terminal leave и удаление
из снимка. Browser дополнительно проверяет обращение/фокус, собственный offline
status, registered badge и прежние сценарии входа, outbox, retry/reload/leave.
React interaction-тест проверяет сохранение DOM строки, взаимоисключающие
статусы, локальный обрыв только для self, счётчик и удаление участника;
boundary-тест отклоняет некорректные новые поля и ended в public snapshot.

Для ручной проверки войти гостем в обе версии; вторую гостевую сессию открыть
в другой вкладке/контексте. На широком экране проверить клик и Enter на нике,
статусы при потере связи и возврате, исчезновение после выхода. На узком
экране проверить отсутствие sidebar и горизонтальной прокрутки. Для просмотра
базового зарегистрированного значка: fixture01 / secret123.
Ручное принятие пользователем ещё не получено. Commit, push и production
не выполнялись.
