## Сценарий и владение данными

`/visits` показывает публичную историю входов за последние 48 часов.
Новый `GET /api/v1/visits` отдаёт только ID записи, ник, время входа/выхода
и фиксированное окно истории. Session ID, identity key, user ID,
resume secret и email не выдаются. HTML и API имеют
`X-Robots-Tag: noindex, nofollow`; ответы не кешируются.

История — read-only application API внутри существующего Go ChatSessions.
Этот контекст уже создаёт/закрывает `visits`; второй владелец записи
или миграций не добавлен. PostgreSQL-адаптер читает существующую таблицу.
Новых миграций, Phoenix proxy/fallback и изменений Phoenix нет.

Сохранены правила legacy:
- нижняя граница окна включается, cutoff округляется до секунды;
- порядок `entered_at DESC, id DESC`;
- одна самая свежая активная запись на точный ник, завершённые сохраняются;
- учитывается время входа, поэтому активный визит старше 48 часов не включается;
- даты выводятся по Москве (UTC+03:00), независимо от timezone браузера;
- страница остаётся снимком: изменение статуса видно после reload/навигации.

React разделён на API, hook и таблицу/строку. DTO генерируются из chat OpenAPI.
Некорректные даты, отсутствующий nullable status, повторяющиеся ID и неверное
окно API отвергаются. Пользовательские ники выводятся текстом.
Загрузка и ошибка не показываются как «пустая история»; предусмотрен повтор
и отмена запроса при размонтировании.

## Визуальная проверка

13 исходных сравнений без масок, CSS overrides и пиксельного допуска:
пустая таблица и история на 390/639/640/768/1440 px, плюс горизонтальная
прокрутка на 390/639/640. Высоты 844/900/900/1024/900 соответственно.
Шрифты и геометрия видимых элементов также сравниваются.
В браузере задана America/Los_Angeles, но отображается московское время.
CSS-переходы завершаются одинаковым `animations: disabled`.

Проверены повторные активные ники, завершённые записи того же ника,
одинаковые entered_at с сортировкой по ID, старые записи, длинный ник,
экранированный `<ник>&`, перенос даты через полночь и мобильная компоновка.
Исправлен порядок скрытой строки пустого состояния: LiveView streams
оставляет её после записей. Это влияет на нижнюю border-collapse/divide-y
границу последней строки, поэтому React сохраняет тот же порядок.

Авторизованный режим проверяется на 390/768/1440. Исходные полные
`*-account-old.png` и `*-account-new.png` сохраняются отдельно.
Как в ранее перенесённой помощи, существующая React `AccountBar`
поднята над декоративным фоном через `relative z-10`; legacy затемняет
панель и перехватывает клики. Диагностический контроль применяет только
это исправление к панели локального эталона: вся страница становится
pixel-exact. Три таких контроля не выдаются за неизменённый legacy.
Проверен выход из React-аккаунта с сохранением публичной истории.

Всего runner: 16 сравнений (13 исходных + 3 диагностических контроля).
Снимки/JSON: `apps/web/migration-results/visits/`.

## Функциональные проверки

- Go unit: collapse active, сохранение завершённых записей, различие регистра
  ника, исходный slice не меняется, публичный DTO/UTC/null, cutoff,
  no-store/noindex, 503 без внутренних деталей и отсутствие write endpoint.
- Go/PostgreSQL: включение ровно 48 часов, исключение 48 часов + 1 секунды,
  порядок и collapse, nullable выход, timestamp-without-time-zone при
  `Asia/Kathmandu`. Сценарий включён в `TestPublicChatPostgres`.
- `verify-go-chat`: реальный вход гостя, видимость активного визита, выход,
  сохранение снимка до reload и завершённый визит после reload.
  Проверены отсутствие приватных полей API, загрузка, ошибка/повтор,
  клавиатурный фокус и именованное окно возврата в чат.
- Frontend unit: московское время при смене суток/года и отклонение
  некорректных/повторяющихся данных API.
