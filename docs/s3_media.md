# Медиа в Selectel S3

В S3 хранятся фото анкет, оригиналы и миниатюры общего фотоальбома, музыка
хит-парада. Пользователи, описания, связи, голоса и ключи объектов остаются в
PostgreSQL. Эмодзи и внешняя музыка из поиска не входят в этот перенос.

## Настройки

Секреты хранятся в `/opt/apps/vertigo-chat/.env` с правами `0600`:

```dotenv
S3_ENABLED=true
S3_ENDPOINT=https://s3.kz-1.srvstorage.kz
S3_REGION=kz-1
S3_BUCKET=vertigo
S3_ACCESS_KEY_ID='...'
S3_SECRET_ACCESS_KEY='...'
S3_PUBLIC_BASE_URL=https://1c6516a8-c238-4cda-8d6b-6fc656183321.srvstatic.kz
S3_VIRTUAL_HOSTED=true
```

Публичный домен нужно взять из вкладки «Домены» бакета. S3 API endpoint и
публичный домен Selectel могут отличаться. Код поддерживает отдельный адрес
выдачи; без `S3_PUBLIC_BASE_URL` используется endpoint/bucket, что подходит не
всем провайдерам. В Selectel бакет должен разрешать публичную раздачу.
Публичные права на запись или удаление не нужны. Существующие правила доступа
сервисных пользователей должны сохраняться.

`S3_VIRTUAL_HOSTED=true` включает адресацию `bucket.s3-domain` для S3 API. Она
нужна для прямой загрузки смайлов из браузера: в Selectel для этого должны быть
включены vHosted-адресация и CORS с origin `https://vertigo-chat.ru`, методом
`PUT` и заголовком `content-type`.

`compose.yaml` передаёт настройки в app, admin и migrate. Без `S3_ENABLED=true`
новые загрузки используют прежнее хранение в БД. После переноса нельзя просто
отключить S3: записи уже ссылаются на объекты, и для их чтения нужны настройки
публичного адреса. Для отката используйте порядок ниже.

Для S3-запросов используется Req и AWS Signature V4. Каждый PUT проверяется
публичным GET с побайтовым сравнением. При сбое новые ссылки не записываются в
БД, старые медиа сохраняются. Частично загруженные объекты могут остаться в
бакете; повторная попытка использует тот же ключ по SHA-256. Автоматического
удаления старых объектов пока нет: это сохраняет возможность восстановления
при замене фото. Очистку нужно делать отдельно по ссылкам из БД и политике
хранения резервных копий.

## Миниатюры

При загрузке фото анкеты сервер создаёт WebP до 480×480, сохраняя пропорции и
ориентацию, без увеличения маленьких изображений. Из превью удаляются метаданные.
Для альбома сохраняется переданная браузером миниатюра; если её нет, сервер
создаёт её из оригинала. При миграции создаются все недостающие миниатюры.
ImageMagick входит в Docker-образ; его потребление ресурсов ограничено.

Списки анкет и фотоальбома используют миниатюры, полный просмотр — оригиналы.
Существующие HTTP-маршруты медиа сохранены: старые записи выдаются из БД, новые
перенаправляются на публичный S3 URL. CSP разрешает домен выдачи только для
изображений и аудио. Миниатюра анкеты: `/profiles/:nickname/photo/thumbnail`.

## Порядок переноса production

1. Выполнить `mix precommit`, создать проверенный релиз по `release_process.md`.
2. Проверить загрузку тестового объекта и публичное чтение через домен выдачи.
3. Проверить чистоту worktree VPS, получить только закоммиченный релиз,
   собрать новый образ, пока текущий сайт работает. Сохранить предыдущий образ
   отдельным тегом для аварийного возврата.
4. Включить S3 в `.env`. Остановить `app` и `admin` на время резервного
   копирования и миграции. Caddy можно оставить работающим.
5. Сделать полный `pg_dump -Fc` вне каталога репозитория (например,
   `/opt/backups/vertigo-chat/`), с правами `0600`. Проверить `pg_restore --list`
   и контрольную сумму; сохранить путь и прежнюю версию приложения.
6. Запустить миграции схемы новой сборкой, затем перенос:

```sh
docker compose --env-file .env --env-file .env.vps run --rm --no-deps migrate
docker compose --env-file .env --env-file .env.vps run --rm --no-deps app \
  /app/bin/chat eval 'Chat.Release.migrate_media()'
```

Перенос обрабатывает записи по очереди, читает ID порциями по 25 и блокирует
строку на время переноса. Все медиа одной записи переключаются одной транзакцией
только после проверки всех её объектов. При ошибке строка сохраняется в прежнем
виде; исправить причину и повторить команду. Уже перенесённые строки пропускаются.

7. Сверить количество ключей оригиналов, миниатюр и аудио с исходными данными;
   проверить отсутствие бинарных медиа в перенесённых строках. Повторный запуск
   должен показать ноль перенесённых записей.
8. Запустить app и admin, проверить healthcheck, фото в списках и анкетах,
   оригиналы альбома, воспроизведение и HTTP Range аудиофайлов. Проверить новую
   загрузку и смену фотографии, не изменяя пользовательские данные ради теста.
9. Сохранить резервную копию до отдельного решения об удалении. Не загружать
   резервную копию БД в публичный бакет. Обычный VACUUM позволит переиспользовать
   освобождённое место; возвращение места файловой системе требует отдельной
   операции и дополнительного простоя, не входит в перенос.

## Откат

До удаления бинарных данных достаточно вернуть предыдущую сборку. После
переноса безопаснее исправить настройки и повторить миграцию: поддерживается
одновременное чтение старых и новых записей. Полный возврат предыдущей версии
требует остановки записей и восстановления резервной копии PostgreSQL; он
потеряет изменения после момента бэкапа и должен быть отдельным решением.
Миграция схемы намеренно запрещает `down`, чтобы случайно не удалить S3-ключи.

- Все временные проверочные объекты удалены. Политика доступа бакета не изменялась:
  выданному ключу Selectel запретил её редактирование. Раздача проверена через
  публичный домен, предоставленный владельцем.
