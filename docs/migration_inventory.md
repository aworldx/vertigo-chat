# Инвентаризация оставшейся миграции

Обновлено: 2026-09-22. Этот документ задаёт порядок последующих срезов в
`codex/go-react-migration`; он не разрешает production rollout.

| Сценарий | Текущее исполнение | Зависимости и границы | Порядок переноса |
| --- | --- | --- | --- |
| Ранги и справка (`/ranks`, `/help`) | `RanksLive`, `Chat.Ranks` | Статические правила рангов; нет записи, сессии, БД или realtime | После UI комнаты; Go read-контракт и React, legacy только для сравнения |
| Визиты (`/visits`) | `VisitsLive`, `Chat.Visits` | Активные визиты, сессии чата, PubSub и учёт времени | После realtime/session протокола; не переносить отдельно от lifecycle |
| Библиотека (`/library`) | `LibraryLive`, `Chat.Library` | Статьи, авторизация, ownership, rank-gate, дневные квоты, URL-параметры | Сначала OpenAPI и read-модель, затем React, затем единый Go writer с транзакциями и квотами |
| Галерея (`/gallery`) | `GalleryLive`, `Chat.Gallery` | Фото/thumbnail, S3, likes, caption ownership, rank-gate, дневные и общие квоты, PubSub | После библиотеки или отдельным контекстом только с контрактом медиа, writer ownership и планом rollback |
| Музыкальный чарт | `MusicChartLive`, `Chat.MusicChart` | Upload, likes/comments, listening/visits, music proxy и realtime | После выделения media и realtime контрактов |
| Игры и шашки | `GamesLive`, `CheckersLive` | Авторизация, PubSub, конкурентные действия, порядок событий | Только в отдельном realtime-этапе |
| Чат и landing | Go entrance/WebSocket и React landing/базовая Room; legacy `RoomLive` для сравнения | Сессии, presence, сообщения уже работают; команды, модерация, медиа, bot-интеграции ещё не перенесены | Следующий этап: полный UI общей комнаты и old/new сравнение; затем остальные действия чата |
| Account/admin/forum | Go Accounts + React login/register готовы; settings/admin/forum остаются legacy | Сессия, учётные данные, SSO, модерация, эксплуатационные права | Переносить оставшиеся сценарии отдельными срезами, не повторять готовый auth flow |

## Ближайший срез: общая комната

Главная и формы проверены отдельно; актуальные результаты и стенды находятся
в [плане миграции](go_react_migration_plan.md) и [отчёте](go_web_verification.md).

1. Сопоставить legacy shell, ленту, composer и online list с текущей React Room.
   Разделить монолитный `Room.tsx` на UI-компоненты по ответственности.
2. Сохранить существующий Go lifecycle и transport; недостающие данные и
   действия сначала описывать контрактом, затем подключать к UI.
3. Проверить отправку/повтор, reload/reconnect, terminal leave, обе роли и
   мобильную навигацию; сравнить одинаковые данные и снимки на трёх viewport.
4. Отдельно перенести остальные действия (команды, настройки, медиа, модерацию,
   личные сообщения), не объявляя базовую комнату полным cutover.

После комнаты ранги/справка остаются небольшим read-only срезом, библиотека и
галерея — отдельными write-контекстами. Каждую область начинать с контракта,
владельца записи/миграций, авторизации, квот, транзакций и отката. Phoenix
используется только из pinned legacy checkout для сравнения: новые fallback,
proxy и LiveView-маршруты в целевой ветке не создаются.
