# Тетрис: правила, протокол и эксплуатация

Реализован в React/TypeScript + Canvas 2D и Go. Новая функция, а не перенос
существующего Phoenix-экрана.

## Вход и приглашения

- `/тетрис` создаёт публичное лобби текущей комнаты. Создатель занимает первое место.
- `/тетрис соло` создаёт личный марафон, без карточки приглашения и зрителей.
- `/тетрис ЛИСА-27` открывает игру по коду и пытается присоединиться.
- `/тетрис топ` открывает `/games/tetris/leaderboard` в отдельной вкладке.
- Повторное создание при наличии активной игры возвращает эту игру.
- Код нечувствителен к регистру, состоит из слова и двух цифр. Он не является
  секретом или разрешением доступа. Постоянные ссылки используют случайный ID.
- Карточка `room_messages.kind=tetris` обновляется на месте через публичный API
  контекста rooms. Обычное сообщение пользователя не может создать такой kind.
  Её body содержит только ID, код, состояние и ники участников.
- Любой человек в комнате, включая гостя, может присоединиться. Один identity
  занимает одно место, серверный mutex защищает лимит 3 и конкурентный старт.
- После третьего участника или старта кнопка вступления исчезает; наблюдение
  остаётся доступным. До старта выход освобождает место.
- Все игроки нажимают «Я готов». Создатель может начать вдвоём или втроём;
  заполнение лобби само по себе не запускает игру. Общий отсчёт — 3 секунды.
- При выходе хозяина из лобби роль переходит следующему игроку. Пустое лобби
  отменяется. Игрок без игровой связи удаляется из лобби через 60 секунд.
- Выход во время отсчёта возвращает остальных в лобби со сброшенной готовностью;
  рейтинг за не начавшийся раунд не начисляется.
- Зритель видит поля и выбирает крупное поле. Он не может управлять фигурой.
- «Реванш» участников одного завершённого матча ведёт в одно общее новое лобби,
  готовность сбрасывается. Участники, уже занятые другой игрой, не перетягиваются.

## Правила

Поле 10×20. Семь фигур, перемешиваемых пакетами по семь. В соревновании все
участники получают один seed и одинаковую последовательность. Дыры атак не
используют генератор фигур. Есть резерв (один раз до фиксации), шесть следующих
фигур и контур приземления. Повороты используют фиксированные небольшие сдвиги
у стен/пола; это собственное правило, не заявление о полном соответствии SRS.

Серверный шаг 50 мс, начальное падение через 850 мс, ускорение на 60 мс за
уровень до 70 мс. Задержка фиксации 500 мс, максимум 15 её сбросов перемещением.
Каждые 10 линий повышают уровень. Клиент детерминированно моделирует своё поле:
падение, задержку фиксации, сброс, очистку, комбо, резерв, генератор фигур и известные
входящие атаки. Сервер независимо выполняет те же правила и остаётся единственным
источником подтверждённых результатов, атак соперникам и рейтинга.

За 1/2/3/4 линии: 100/300/500/800 × уровень до очистки. Со второй подряд
очищающей фигуры бонус комбо 50 × номер цепочки × уровень. Фигура без очистки
обнуляет цепочку. Опускание: мягкое 1/клетку, мгновенное 2/клетку.

В соревновании за 1/2/3/4 линии атакуют 0/1/2/4 серыми строками. Своя атака
сначала гасит входящую очередь. Остаток уходит одному живому сопернику;
при троих цель чередуется. Очередь ждёт 1500 мс и применяется после фиксации
фигуры. Каждая строка оставляет одно отверстие. Переполнение завершает игру.

Один матч — один раунд. Последний живой игрок побеждает. Выбывшие в одном
серверном шаге имеют одинаковое место. После потери игрового соединения есть
20 секунд на восстановление после последнего подтверждённого контакта в сетевом матче;
сетевой раунд не приостанавливается. При известном обрыве клиент прекращает ввод;
без свежих снимков прогноз ограничен двумя секундами, после чего появляется
«Синхронизация…». Старые действия после восстановления не переигрываются. Перезагрузка восстанавливает игру в той
же вкладке. Пауза доступна только в соло. Выход из начавшегося раунда — поражение.

## Рейтинг

Сохраняются только результаты, сформированные сервером. `tetris_results.id`
защищает от двойного сохранения; счёт и рейтинги записываются одной транзакцией
под advisory lock. Гости играют, но не входят в постоянную таблицу. Матч с
гостем не меняет соревновательный рейтинг зарегистрированных участников.

Начальный рейтинг 1000. Для пары ожидание:
`E = 1 / (1 + 10^((R_opponent - R_self) / 400))`.
Фактический результат S: 1/0.5/0 за победу/равное место/поражение.
Изменение: `32 × sum(S - E) / (число участников - 1)`.
Для каждой пары учитываются первые три встречи за сутки UTC. Остальные пары
матча могут продолжать влиять, делитель остаётся исходным. Рейтинг хранится
дробным и округляется только в представлении. Победа в статистике — единоличное
первое место, равное первое место победой не считается.

Месячный рейтинг независим от общего и начинается с 1000. До пяти рейтинговых
матчей показывается калибровка. Соло — лучшая завершённая партия пользователя
за период; при равных очках первым показывается более ранний рекорд. Таблица
ограничена первыми 100 участниками. Границы месяцев/суток — UTC, даты рекордов
в интерфейсе — Москва. Игровой рейтинг не меняет карму чата.

## HTTP и WebSocket

DTO генерируются из `contracts/openapi/tetris.yaml`; актуальность включена в
`script/check-contracts`. Все игровые HTTP-запросы используют существующий
resume credential в `Authorization: Bearer`. Мутации проверяют Origin.
Публичный leaderboard не требует входа. Credential никогда не попадает в URL.

`GET /api/v1/tetris/{id}/socket` проверяет Origin; в течение 5 секунд клиент
передаёт `{"type":"auth","token":"<resume credential>"}`. Авторизация выполняется
через read-only Credentials API chatsessions без изменения generation основного
соединения чата. Каждые 10 секунд проверяются сессия и ping. Завершённая сессия
закрывает игровое соединение. Вторая игровая вкладка той же identity и игры
закрывает предыдущую, не затрагивая основной чат.

Клиентские команды: `join`, `ready`, `unready`, `start`, `leave`, `left`, `right`,
`down`, `rotate`, `counterrotate`, `drop`, `hold`, `pause`.
Формат: `{"type":"left","sequence":123,"piece_id":7}`. Для игровых действий sequence строго
возрастает; повторы игнорируются. Вход ограничен 40 командами/с и 32768 байтами.

Сервер передаёт `{"type":"state","game":TetrisGame}` при изменении состояния и
`{"type":"error","message":"..."}` при отклонении действия. DTO не содержит
identity, user_id, resume credentials или исходный seed. Только владелец своего поля
получает `simulation`: номер фигуры, таймеры падения/фиксации, число сбросов
таймера, комбо, текущее состояние RNG/мешка и известную очередь атак. Зрители и
другие игроки этот checkpoint не получают. `revision` упорядочивает снимки. У каждого игрока есть последний
подтверждённый sequence, чтобы клиент мог повторно применить неполучившие
подтверждения прогнозы. В сетевом матче после обрыва неподтверждённый ввод не переигрывается.

## Независимое соло

В auth клиент передаёт client_clock:true; сервер подтверждает режим в Game DTO.
После стартового отсчёта собственное время соло ведёт браузер. Гравитация,
фиксация, линии и ввод не имеют двухсекундного сетевого барьера.
Подтверждения освобождают журнал, но не перематывают живое поле.

При наличии изменений клиент каждые 250 мс отправляет replay с through_ms и
inputs:[{type,sequence,piece_id,at_ms}]. Сервер принимает только решения владельца,
проверяет последовательность, шаг 50 мс и предел реального времени, сам
воспроизводит фигуры и очки. Пакет ограничен 128 событиями и 10 секундами
симуляции; большой разрыв догоняется несколькими пакетами. Подтверждённые
sequence повторно не применяются; ошибочный пакет отклоняется целиком.
Клиент не передаёт очки, клетки или RNG. Только проверенный результат попадает
в существующее транзакционное хранилище. Старые клиенты сохраняют прежний режим.

Журнал хранится в открытой игре: закрытие или reload до восстановления связи
может потерять неподтверждённые ходы. Истечение сессии чата и перезапуск API
могут помешать сохранению результата. Неактивная серверная запись отменяется
через час. Это независимая игра во время кратких разрывов, без гарантии
долговременного offline-хранения.

browser/tetris-solo-async.ts проверяет настоящий Go API в popup/mobile:
ответы задержаны более двух секунд, popup отключён на 22,5 секунды,
последующий локальный ввод и серверный replay дают те же очки после reload.

## Хранение и ограничения

Миграция `0007_tetris.sql` принадлежит Go и добавляет только таблицы результатов,
счёта и рейтингов. Данные других контекстов не изменяются. Применение — существующей
командой `go run ./cmd/migrate` в процессе разрешённого выпуска, не этим заданием.

Активными матчами владеет один API-процесс. PostgreSQL session advisory lock
674923008 предотвращает запуск второго владельца на той же БД. Для нескольких
API-реплик в будущем потребуется отдельный владелец игрового цикла или маршрутизация.
Перезапуск отменяет активные приглашения без рейтинга, завершённые сохранённые
результаты остаются. Одновременно удерживается не более 1000 матчей; завершённые
удаляются из памяти через час после сохранения. Отменённое лобби нельзя пересоздавать
чаще одного раза в 10 секунд. Ошибки сохранения логируются и повторяются.

Canvas читает игровое состояние независимо от React через подписку; кадры
запрашиваются у окна, в котором находится поле, включая popup. React обновляет
оболочку при изменении счёта, очереди фигур и других отображаемых метаданных. Звуковая дорожка
синтезируется локально через Web Audio: без внешних файлов и автозапуска, с отдельной
громкостью музыки и эффектов. При скрытии вкладки звук приостанавливается.

«Включить звук» находится над полями и проигрывает пример. Внизу доступны
«Проверить звук», «Музыка» и «Звуки игры». Перемещение, поворот и сброс звучат
сразу при вводе; фиксация и схлопывание линий — по локальному состоянию поля. Фиксация распознаётся и при одинаковых соседних фигурах. Начальная
громкость звуков игры — 70%, музыки — 18%.

Первое перемещение немедленное; при удержании через 150 мс начинается повтор
каждые 45 мс. Обновления состояния не сбрасывают удержание. Симуляция использует шаг 50 мс и отрисовку через requestAnimationFrame.
В сетевом матче ввод отправляется сразу, без очереди с отправкой по таймеру. В соло ввод немедленно применяется локально, журнал отправляется независимо от игрового цикла. Ограничение 35 команд/с
на клиенте не создаёт backlog; сервер сохраняет собственное ограничение 40 команд/с.
Команды привязаны к номеру фигуры: поздняя команда подтверждается без воздействия
на следующую фигуру. При сверке повторяется только неподтверждённый ввод текущего
соединения с сохранением порядка и времени локальных шагов.
После pointer-нажатия кнопки игрового окна фокус возвращается полю; Tab и
клавиатурная активация сохраняют нативную семантику кнопок. Браузерная проверка блокирует ответы игрового WebSocket и
проверяет изменение пикселей Canvas до ответа сервера, а также запуск звуков
перемещения, примера и фиксации через Web Audio. В прогоне 2026-09-27 локальный
сдвиг занял 28 мс; это измерение тестового окружения, не гарантия для всех устройств.

## Проверка

- Go unit/race: правила, очередь атак, ограничения лобби, права, тайм-ауты,
  идемпотентность ввода, приватность, конкурирующее занятие мест.
- Общие координаты фигур: `contracts/fixtures/tetris-pieces.json`, проверяются
  сервером Go и клиентом TypeScript.
- PostgreSQL: idempotent save, рейтинг обоих периодов, лимит повторных встреч,
  матчи с гостями, лучший одиночный результат.
- `script/verify-go-tetris`: отдельная одноразовая БД и API localhost:4067,
  четыре настоящие браузерные сессии, команды/приглашения/наблюдение/готовность,
  ранний старт вдвоём, матч втроём, реванш, reload, соло, звук, лидерборд.
- Снимки в `apps/web/test-results/tetris`. Самостоятельная новая игра не имеет
  Phoenix-эталона; сравнение идентичных legacy игровых экранов неприменимо.
- Игровой browser suite и PostgreSQL-тесты включены в общий coverage gate.

Итог локальной проверки 2026-09-26: `mix precommit` и
`script/check-infrastructure` прошли. Покрытие Go API 90,06%, React 93,1%,
worker 92,05%; Phoenix — 411 тестов. Проверены снимки игры 1440×900, 768×1024
и 390×844. В тестах приложения проверены повторное сохранение после отказа БД,
отсутствие повторной записи успешного результата и границы доступа к реваншу.

## Проверки локальной симуляции (4 октября 2026)

`contracts/fixtures/tetris-simulation.json` — общие трассы Go/TypeScript: падение,
повороты, резерв, 15 сбросов lock delay, одиночные/четыре линии, комбо, смена
уровня, отмена/применение мусора и top-out. Тест Go сравнивает трассы с текущим
доменом; TypeScript проигрывает их и сравнивает полные состояния доски.
Обновление трасс — только явно через `UPDATE_TETRIS_FIXTURES=1` в Docker.

`browser/tetris-cycle.ts` проверяет редкие состояния на фиксированных checkpoint
через настоящий Canvas/UI. `tetris-feedback.ts` удерживает ответы настоящего
игрового сервера и проверяет движение, сброс, следующую фигуру и фокус звука.
Основной suite сохраняет настоящие multiplayer, observer, reconnect, popup,
mobile, pause, score и leaderboard сценарии. Визуальные эталоны и отчёт:
`docs/design/tetris-cycle/`.
