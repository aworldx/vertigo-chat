# Покрытие целевого стека

Обязательный порог — **90% отдельно для Go API, React и YouTube worker**.
Legacy Phoenix не включён в этот порог по решению пользователя. Его обычные
проверки `mix precommit` сохраняются.

- API: statement coverage всех пакетов `apps/api`, включая команды запуска и
  миграций. Объединяются unit-тесты, интеграционные тесты PostgreSQL и выполнение
  инструментированного API в браузерных сценариях.
- Worker: statement coverage всего модуля `services/youtube-worker`, с race detector.
- React: не менее 90% строк и statements V8 для всех `.ts`/`.tsx` в `apps/web/src`.
  Объединяются unit-тесты c8 и Chromium JS coverage через source maps. Неисполненные
  файлы включаются через `c8 --all`. Исключены только сгенерированные OpenAPI-типы.
  Functions и branches выводятся в отчёте, но не являются метрикой этого порога.

Проценты компонентов не усредняются. Для Go сравниваются целые числа до округления:
89,99% не проходит. Отсутствующий, пустой или несовместимый отчёт — ошибка.

`mix precommit` полностью прошёл, включая 411 ExUnit-тестов и 3 browser-проверки

detector. Запас API над порогом небольшой: новый непокрытый код может блокировать
следующую сборку — это ожидаемое поведение gate.

## Локальный запуск

Нужны Go 1.27.1, Node.js 24.8+, PostgreSQL client/server, ImageMagick и Chromium
Playwright. После `npm --prefix apps/web ci` установите браузер через
`cd apps/web && npx playwright install chromium`.

```sh
COVERAGE_DATABASE_URL=postgresql://localhost/postgres script/check-coverage
```

`GO` позволяет указать абсолютный путь к Go. Пользователь PostgreSQL должен иметь
право создавать и удалять тестовые БД. Скрипт создаёт собственные временные базы,
загружает только схему `script/fixtures/legacy-schema.sql` и синтетические fixtures,
а при завершении удаляет созданные базы. Production-данные не используются.

Отчёты каждого прогона пересоздаются:

- `coverage/go/api.cover` — объединённый API;
- `coverage/go/worker-total.cover` — worker;
- `apps/web/coverage/index.html` — React, включая детализацию по исходникам;
- `apps/web/coverage/coverage-summary.json` — машиночитаемый React summary.

Coverage-сборка React не минифицируется: это необходимо для корректного
сопоставления V8 ranges и TSX source maps. Обычная production-сборка остаётся
минифицированной. Сборщик сохраняет промежуточные события Chromium precise coverage и итог перед
закрытием страницы. В coverage-режиме он также приостанавливает документ через
CDP в `beforeunload`, снимает диапазоны и немедленно продолжает навигацию.
Эта инструментализация не входит в production assets. Иначе V8 может удалить данные
предыдущего документа, особенно в Linux, даже при `resetOnNavigation: false`.
Отдельный smoke-тест gate проверяет сохранение coverage после навигации и
принудительной сборки мусора на восьми последовательных документах. Нельзя смешивать отчёты разных
версий исходников. Промежуточные V8-диапазоны объединяются **до** конвертации
через source maps: отдельная конвертация deltas может завысить число покрытых
строк. Gate отдельно проверяет, что невызванная функция остаётся непокрытой,
и отклоняет отчёты с разными версиями JS bundle.

## Quality gate

`mix precommit` вызывает `script/check-coverage`. GitLab quality job запускает
тот же скрипт в контейнере с отдельным PostgreSQL. Production build зависит от
успешного quality job. Функциональные браузерные сценарии gate работают на Go +
React; legacy-сравнение снимков остаётся отдельной обязательной проверкой миграции.

Покрытие не заменяет аудит, визуальную проверку и тестирование жизненного цикла
вкладки. Порог подтверждает исполнение кода тестами, а не отсутствие дефектов.
