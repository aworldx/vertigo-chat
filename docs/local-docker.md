# Локальный Docker-стенд

Запуск из корня репозитория:

```sh
./script/dev-docker
```

Скрипт использует закрытый, игнорируемый Git файл `.env.docker.local`.
Можно передать другой файл первым аргументом. Его переменные соответствуют
`deploy/compose.yaml`; для существующего стенда нужно сохранить прежние
`POSTGRES_*`, `DATABASE_URL` и имя проекта `chat-cutover`, чтобы использовать
существующую локальную БД. `DATABASE_URL` должен указывать на сервис `postgres`.
Локальный origin — `http://127.0.0.1:4063`, Caddy address — `http://:80`.
Секреты хранятся только в локальном env-файле с правами `600`.

Скрипт запускает приложение, PostgreSQL, YouTube worker и Caddy, затем включает
Compose Watch (Docker Compose 2.24.4+). Изменения `apps/web`, `apps/api`, worker
и Dockerfile автоматически пересобирают соответствующий образ и пересоздают
контейнер. Артефакты сборки и `node_modules` исключены из наблюдения.
API применяет встроенные миграции перед каждым запуском. Данные БД остаются
в существующем volume.

После успешной пересборки обновите страницу браузера. Во время перезапуска API
возможен короткий разрыв соединения. Это пересборка, а не React HMR.
Ctrl+C останавливает наблюдение; контейнеры продолжают работать. Повторный запуск
скрипта снова включает наблюдение. После перезагрузки компьютера запустите скрипт
заново. Не запускайте несколько наблюдателей одновременно.

Конфигурация локального наблюдения находится в `deploy/compose.local.yaml`;
production Compose не включает её.
